# 验证批次（v0.2.1）

用途：回答“这套流程能否稳定地产出用户愿意采用的成片”。用户明确要求做验证批次时执行；平时正常修图不需要。

## 1. 照片组成（共约 20 次运行）

- **15 张新原片**，尽量覆盖：带招牌或文字的街景（≥3）、有行人的场景（≥3）、夜景或弱光（≥2）、自然风景或园林（≥2）、建筑立面或细部（≥2）、室内（≥1）、其他（玻璃、动物、车辆等）。
- **重复一致性**：从中挑 3 张，**各在一个新对话里再跑一次**（同一原片、同一版本），比较两次结果。
- **iOS**：至少 3 张在 iPhone 上的生图大模型 agent App 里跑（见第 4 节）。

每张照片照常处理：用户只发照片和一句修图请求，执行者按 `SKILL.md` 的“默认执行”完成，并在累计标记表追加一行。v0.3.0：验证批次期间每张都在成片下附标记表新增的那一行，并记录能力级别、是否自动加码、是否走了保底；有条件时在第二种 agent 上重复 3 张，比较结果。

## 2. 统计什么

| 指标 | 怎么算 |
|---|---|
| 交付率 | 没有硬 STOP 的照片数 ÷ 新原片数 |
| 采纳率 | 用户标为接受的成片数 ÷ 交付的成片数 |
| 强度达标 | 正常观看下有明显光影或色彩提升的成片占比（执行者判断，用户可推翻） |
| 故事感 | 用户认为“讲出了这张照片的故事和风格”的成片占比（v0.2.2；用户每张答“到位／不到位”，不答视为未评） |
| G 重跑率 | 用了第二次 G 的照片占比，以及重跑后是否改善 |
| 重复一致性 | 3 张重复的照片中，两次都交付且用户都能接受的张数 |
| STOP 原因分布 | 按总则四种情况分类计数 |
| iOS 结果 | 技能是否可见、是否走了附件模式、成片能否存入相册 |

## 3. 暂定目标（由用户确认或修改）

交付率 ≥ 80%，采纳率 ≥ 80%，强度达标 ≥ 80%，故事感到位 ≥ 70%，重复一致性 3 张中至少 2 张，iOS 至少能用附件模式完成并存入相册。

全部达到即视为达到交接文件中的完成标准；未达到的项交规则维护者统一调整，**不在批次中途改规则**。

## 4. iOS 做法

1. 在 iPhone 上的生图大模型 agent App 里新开对话，只发照片和一句“修一下这张”。
2. 若执行者能看到并读取 photographic-studio：照常处理，在标记表“运行端／模式”写“iOS／安装副本”。
3. 若看不到：在同一对话里附上已批准的规则包 zip，并说“按附件里的 Photographic Studio 处理”。执行者核对 zip 内 `SHA256SUMS.txt` 全部一致后照常处理，写“iOS／附件模式”。
4. 成片出来后在 iPhone 上长按存入相册，把能否保存、相册里的尺寸写进标记表。

## 5. 批次结束时输出

完整累计标记表，以及第 2 节各指标的数值和一段不超过五行的总结（达到／未达到哪些目标、最常见的标记和 STOP 原因）。
