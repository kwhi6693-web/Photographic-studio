# 个人风格库（v1.3.0，可选，默认关闭）

风格是“调味”，不是“换菜”：每张照片先按它自己的问题写导演单、定参数，风格只把全局参数往用户口味推一点。读片、提升动作、不能动的区域、全部检查都不变。用户 2026-11-15 把它加入开发（给所有用户的功能），2026-11-19 确认版本稳定后可以记住风格与反馈。

## 1. 什么时候用

- 只有用户建过风格、而且没有说“关风格”时才用。没有风格档案就照常修，不提风格。
- 用户只说“修”时，有风格就自动用，不问。

## 2. 风格档案存在哪（先判断宿主属于哪一类）

用户说“建风格”或第一次要用风格时，先试一次：往长期记忆写一条测试记录，再读回来。结果写进回执。

| 类型 | 判断 | 档案放哪 | 修后反馈 |
|---|---|---|---|
| A 能写也能读 | 写入成功，新对话也读得回 | 宿主长期记忆，存 `style_profile.json` 的全文 | 自动写回记忆 |
| B 只能读 | 能读到，但写不进 | 宿主记忆；更新要用户说“更新风格” | 先记在当前对话，用户确认后写入 |
| C 不能记 | 写不进，也读不到 | 用户手机里的 `style_profile.json`，修图时一起发 | 交付时附上更新后的文件 |

实测（2026-11-19）：Gemini 是 A 类；image2.6 的 Work 会话是 C 类（它能从历史聊天里翻到原文，但这不算可靠存储）。C 类的用户忘了附文件时，按没有风格修，并在交付行后加一句“这次没有用你的风格（没收到风格文件）”。

## 3. 用户的几句话

| 用户说 | 做什么 |
|---|---|
| 建风格 + 3–10 张照片 | 有原片和自己修好的成片就成对给：`style.py build 档案 --pairs 原片1 成片1 …`；只有喜欢的照片：`--finals 图1 图2 …`。按题材建（例如只发夜景）时加 `--genre=night`。照片只用来量数字，不保存 |
| 关风格 / 开风格 | 把档案里的 `on` 改成 false / true |
| 看风格 | `style.py show 档案`，用一两句话说清楚口味，再列反馈记录 |
| 忘掉风格 | A/B 类删掉记忆里的档案；C 类告诉用户可以删掉那个文件 |
| 修完说一句（“太暖了”“再通透一点”） | 先按这句话改这张照片的导演单重做（原有规则）；风格开着时，再按下表记一条反馈 |

反馈对照（一句话只记一个方向；说不清的不记）：

| 用户的话（举例） | `--param` | `--dir` |
|---|---|---|
| 太暖了 / 太黄了 | warm | -1 |
| 太冷了 / 太蓝了 | warm | +1 |
| 太艳了 / 颜色太重 | colour | -1 |
| 太灰了 / 颜色再浓一点 | colour | +1 |
| 反差太大 / 太硬 | contrast | -1 |
| 太平了 / 再有层次一点 | contrast | +1 |
| 太暗了 / 再通透一点 | depth | +1 |
| 暗部太亮 / 压一压暗部 | depth | -1 |
| 太锐了 / 太硬了（质感） | clarity | -1 |
| 再清楚一点 / 质感不够 | clarity | +1 |

命令：`style.py feedback 档案 --param=warm --dir=-1 --words="太暖了"`（有题材就加 `--genre=`）。同一个方向说得越多，信心越高；反方向会降低信心。

## 4. 修图时怎么用

1. 第 3–4 步照常读片、写导演单，不看风格。
2. 给 G 的提示词末尾加一句：`整体口味：<style.py words 的结果>`。没有词就不加。不写数字。
3. 第 5 步运行 `finish.py … --style=档案`（照片属于某个已建的题材时加 `--style-genre=`）。`finish.py` 先试“导演单 + 风格”，风格让物理检查不过就自动退回不加风格的导演单；只超出力度上限的，保留风格，第 6 步 `settle.py` 去掉超出的部分。
4. 回执里的 `style` 写着风格改了哪些参数。交付行不变，不额外说明用了风格。

## 5. 守住的底线

- 每个参数最多推它允许范围（半幅）的三分之一，再乘以信心。
- 不碰提升动作、不碰不能动的区域：风格偏冷，夕阳照样是暖的。
- 物理检查不过就不用风格；照片各自的参数仍然各不相同。
- 不从网上抓风格，不提供多套风格切换。
