# Photographic Studio v1.2.1

**v1.0 规则文字已获用户批准（2026-11-12）；v1.0.1 是用户委托维护者做的一致性修订，不改变修图效果。** 独立的非人像摄影后期 Skill：用户从手机相册发一张照片、说一句“修”，就得到一张有明显摄影表现力、仍然高度像原片、符合自然光规律、看不出 AI 痕迹的成片。面向任何能看图的 agent；需要具备生图能力的大模型 agent；目前在 image2.6 上实测过（手机与网页版）。

## 它怎么工作

1. **读片和导演单**：读出这张照片的看点（叙事只是一种，还有几何、光影、色彩、质感、氛围等）、主角和风格方向，逐条诊断问题，参数只来自诊断（导演单）。
2. **G 只给光和色**：调用宿主的图像编辑工具（G）一次；成片的每个像素来自原片，只带上 G 的光线和色彩，所以文字、人物、纹理都是原片的。
3. **N 精修**：确定性调色工具按导演单补齐。
4. **自动检查和兜底**：物理检查（不造光、不删光、明暗次序、光晕等）和力度检查（只拦超出上限和看不出变化；博物馆题材按主角判断）。不合格就自动换下一级重做，直到 N 直出，始终交出一张成片。之后 `settle.py` 只去掉超出上限的部分，再按导演单逐条验收、做构图重构。
5. **只交一张成片**，加一行“看点｜风格”和成片标签。

## 包里有什么

- `SKILL.md`：唯一的执行说明。
- `references/`：总则、读片和处方、七类题材、导演单、G 提示词、物理、力度、自然度、贴回、构图、交付、口味参照、验证批次。
- `optional/`：工具（需要 numpy、Pillow、OpenCV）。
  - `finish.py`：默认路线一步完成，含自动重做阶梯。
  - `look_transfer.py`：原片像素 + G 光色；拦下 G 凭空加的光和删掉的光。
  - `grade.py`：按导演单调色。
  - `physics_check.py`、`intensity_check.py`：物理与力度检查。
  - `settle.py`：第 6 步，只去掉超出上限的部分。
  - `keep_regions.py`：导演单里“不能动”的区域，颜色不被带偏、内容不被 G 重画（v1.1.0）。
  - `improve_check.py`：导演单的每个提升动作在成片里是否看得出，以及动作边缘有没有在天空里留下光圈（v1.2.0）。
  - `full_res.py`：把小尺寸上的修图带回原图尺寸（引擎用）。
  - `check_g_output.py`、`measure.py`、`selfcheck.py`、`reframe.py`、`n_trim.py`、`text_restore.py`、`texture_blend.py`、`ps_common.py`。
- `assets/taste/`：用户早期认可的 6 组原片与成片对比（历史记录；v1.0.9 起默认流程不读）。**这是用户自己的照片，转给他人前请确认。**
- `CHANGELOG.md`：v0.1.1 – v0.3.8 的完整变更记录。
- `SHA256SUMS.txt`：全部文件的校验值。
- `LICENSE`：MIT（2026-11-14 起，此前为 AGPL-3.0），适用于执行说明、参考文件和工具；`assets/` 里的照片版权归作者，不在许可范围内。
- 工具回执里的版本号是该工具**最后一次改动**的版本，所以各工具不同。

## 用法

- 已安装：直接发照片说“修”。
- 附件方式：在对话里附上本 zip，说“按附件里的 Photographic Studio 处理”；执行者先核对 `SHA256SUMS.txt`。
- 其他说法：“精修”（多候选，更慢）、“看回执”、“看标记表”、“验证批次”。

## 已验证的

- 2026-11-11 iOS 实跑：v0.3.7 快速验收 6 次，用户采纳 3 次（垂柳、铜牛灯、澳门塔）；看不出变化的 3 次（蓝釉瓶两次、青瓷罐）促成了 v0.3.8 的博物馆力度；v0.3.8 蓝釉瓶实跑与用户选定的第 3 档一致。
- 维护者本地：7 组固定样本 × 7 个工具的回归测试；第 1 批 6 次的 G 稿重放。

## 已知限制

- 验证样本少：采纳率、重复一致性等统计目标（`validation_protocol.md`）没有跑完整批次，不能说“稳定达标”。
- 成片尺寸受宿主上传压缩限制（长边约 1536 像素）。
- 新判断规则（纹理随光、删光、博物馆力度）只在十几张照片上定过阈值。
- 青瓷罐那类 G 重画了暗部纹样的情况，光色迁移仍可能留下淡斑（用户看不出）。
- 日光题材力度不足时，没有自动加码一级，由执行者按提示补。
- 不能复现历史上某次生成的确切结果；复现的是决策方法、约束和检查。

## v1.2.1 相对 v1.2.0（2026-11-15）

起因：用 v1.2.0 实跑同样三张，三张都有了提升动作，但三张又都没调用 G（理由是“每个动作均为 N 支持”——这个条件对任何提升动作都成立）；动作只写到刚过最低线，城楼与原片的平均差仍只有 2.1；城楼横跨全幅的晚霞带被光圈修正改成“只作用在有结构的地方”，晚霞的提升随之消失；古籍局部反差 0.4 在 797 像素的原片上出了颗粒。规律：agent 能选择少做的地方，就会少做。

- **T1 每张都调用 G**，不再由导演单决定；`--no-g` 只给没有 G 的宿主。引擎去掉“跳过图像模型”。
- **目标幅度**：`improve_check.py` 除了最低线，还给每个动作一个目标（用户认可的六组成片的中位水平：明暗 4 L*、色彩 ×1.25、冷暖 2.5、局部反差 ×1.18）；`finish.py` 把没达到目标的动作加强（每轮 1.4 倍、最多三轮），物理检查或强度上限拦住就停。只有低于最低线才算失败。
- **带状区域的光圈**：横跨全幅的天空、水面带改成更柔的过渡，局部动作仍改成只作用在有结构的地方。
- **低分辨率**：短边不到 900 像素时，所有局部反差最多 0.2。
- **裁切后不再测量**：`improve_check.py` 遇到画幅不同的成片直接跳过（之前在裁切后的城楼上误报“看不出”），以 `finish.py` 回执为准。
- 本地对照（没有这三张的 G 稿，以下都是 N 直出）：GPT 这次写的导演单在 v1.2.1 下，湖景、古籍、城楼与原片的平均差为 5.6、9.0、4.6（v1.2.0 实跑为 6.2、14.0、2.1；古籍降低是因为局部反差被限到 0.2）；城楼的晚霞带不再被修没，加强到第二轮时被暖色上限拦住。有 G 之后的效果要实跑才能看到。

## v1.2.0 相对 v1.1.0（2026-11-15）

起因：用 v1.1.0 实跑三张（枝叶框景湖景、展柜古籍、暮色城楼），三张都被判成“光线已经很好”、跳过 G，湖景和城楼与原片的平均差只有 2.9 和 2.2（满分 255），肉眼看不出；回执显示导演单把整张照片写成“不该动”，强度检查报了“低于下限”却被规则要求忽略，自评全部 ✓。同样的事在 v0.3.3、v0.3.7、v1.0.1 都出现过。根本原因是整套规则以“别改坏”为先，没有任何东西推动“修得好”。用户要求一次找到根本问题、针对性解决，不再逐条修补。

- **导演单先定成片目标**：2–3 个提升动作（`moves`），每个落在一个区域、修完要看得出；没有缺陷的照片也要有。“不该动”只列关键事实（文字、人物、结构、标志性颜色）。
- **N 能做局部动作**：`grade.py` 的区域新增 `clarity`（区域内局部反差）和 `on_structure`（只作用在有结构的东西上，不在平整的天空、墙面上留下光圈）；`moves` 按区域来调。
- **提升检查**（新工具 `improve_check.py`）：每个动作在它的区域里量变化（明暗 ≥2.5 L*、色彩 ≥×1.10、冷暖 ≥1.5、局部反差 ≥×1.08，略低于用户认可过的最克制的一张）；`finish.py` 把看不出的动作加强 1.5 倍（最多两轮，物理检查仍通过、不超上限才采用）；动作边缘在天空等平整处留下光圈或色圈（只计这个动作自己的那部分改动）时，自动改成 `on_structure`。
- **验收顺序倒过来**：先核对每个提升动作“正常尺寸看得出吗”，再查缺陷、关键事实、自然度和物理；“仍是原来的蓝”这类没改的证明不算提升。
- **跳过 G 只在一种情况下**：每个提升动作都是 N 能做到的区域调整，并写明理由；`finish.py --no-g`（或把原片当 G 稿）走独立的 N 通道，不再对原片自己做光色迁移。v1.0.9 的“光线已经很好就不调用 G、只轻修”取消。
- 引擎 2.3.0：导演单新增 `moves`（校验后写进参数），`light_already_good` 只在每个动作 N 都能做到时才跳过图像模型。
- 本地对照（同样三张原片，导演单按新规则写，见 `tests/fixtures/improve/`）：三张全部“看得出”；湖景天空上方亮度 −3.6、叶片色彩 ×1.19、水面局部反差 ×1.18；古籍书页 +4.2、纸墨反差 ×1.28；城楼晚霞色彩 ×1.31、灯光色彩 ×1.17、倒影 ×1.18。城楼的第一版导演单用椭圆提亮，留下了天空光圈（物理检查没有发现），新的光圈检查发现了它，改成只作用在建筑上之后消失。
- 没做到的：导演单仍由 agent 写，它会不会真的写出好的提升动作，要看实跑；阈值只在这三张和用户认可的六组口味样本上校准过；G 路线下的提升检查还没在真实 G 稿上跑过。

## v1.1.0 相对 v1.0.9（2026-11-15）

目标（用户，综合 AI 修图的四个难点之后）：先解决局部控制——全图追色会把颜色带到不该改的地方，G 会在局部重画原片没有的内容。

- 新工具 `keep_regions.py`：导演单把不能动的区域写进参数文件的 `keep`（物体名称、大致的框、`colour` 或 `content`）。框会按原片的边缘收紧并柔和过渡；`colour` 保留原片颜色、亮度跟着修图走；`content` 保留原片自己的细节和颜色，只带上修图在大范围上的光和色调。分界检查：分界两侧的颜色台阶比原片多出 3 ΔE 以上，先加宽过渡重试一次，仍然看得出就标 `KEEP_SEAM`。
- `finish.py`：在光色迁移和调色之后、检查之前执行这些区域，所以每一级重做（包括 N 直出）都带着它们。
- 引擎：导演单新增 `keep_regions`，校验后写进参数。
- 测试：整幅偏暖时 `colour` 区域内的颜色回到原片、区域外不变；b2_01 屏风左扇（G 画出了原片没有的牡丹），`content` 区域内原片细节的误差减半以上、整体的暖调仍然进来、分界 2.2 ΔE（看不出）；框横穿平整天空时分界检查会报出（4.0）。参数里没有 `keep` 时，所有输出与之前逐字节相同。
- 没做到的：b2_01 即使保护了屏风，仍因 G 在暗处造的光和主角过艳退回 N 直出（与重画无关）；`colour` 模式还没有在真实照片的真实物体上验证过；框由 agent 估计，偏差多大要看实跑。

- 现有 `grade.py` 用 `levels.black` 8 加 `contrast` 0.12 就能去掉那张的雾，缺的是判断，不是工具。
